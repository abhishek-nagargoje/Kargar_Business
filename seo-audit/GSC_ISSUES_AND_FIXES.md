## October 2026 review (GSC screenshots dated 22 Oct 2026)

All results below are from real GET requests against production on 22 Oct 2026. Raw data is in `seo-audit/production/` (`redirects.csv`, `canonicalization-matrix.csv`, `internal-links.csv`, `external-links.csv`).

| Page with redirect | `/services/` | `308 Location: /services` → `200`, self-canonical, in sitemap | Vercel platform, `"trailingSlash": false` in `frontend/vercel.json` | **Intentional.** One permanent hop to the canonical URL. Nothing to fix |
| Page with redirect | `/sectors/` | `308 Location: /sectors` → `200`, self-canonical, in sitemap | Same | **Intentional** |

**Why the privacy-policy error can't be pinned down further:** `/privacy-policy`'s routing in `vercel.json` (rewrite to the prerendered `/privacy-policy.html` plus `trailingSlash:false`) has not changed since 8 Sep 2026, so it was the same throughout the validation window (21 Sep to 16 Oct). The page has no client-side redirect (`PrivacyPolicyPage.tsx` has no `<Navigate>`). The most likely explanation is a transient fetch failure on Google's side, or on Vercel's side during the crawl. Proving that needs the Vercel deployment and request logs for 16 Oct. Those could not be read from this machine: the Vercel API returned 403, and `frontend/.vercel/project.json` points to a project the CLI cannot load. The redirect behaviour is now covered by audit probes (below), so a regression would fail CI.

**Full canonicalization matrix:** 7 key routes × {http, https} × {www, apex} × {slash, no slash} = 52 variants. Every one ends on the `https://www` no-slash canonical URL with `200`, and none loop. The longest chain is 3 hops (`http://apex/x/` → https → www → slash strip). Vercel applies those domain-level hops before `vercel.json`, so they can't be merged there, and they're well within Google's limits.

**Other findings in this pass**

- The Organization JSON-LD `sameAs` listed `https://in.linkedin.com/company/kargar`, which returns **404**. That URL is a different LinkedIn page from the footer's verified company page. **Fixed:** `sameAs` is now generated from `src/config/socialLinks.ts` (the same list the footer renders).
- The footer LinkedIn link had an admin-only `?viewAsMember=true` parameter. **Fixed:** it now uses the clean URL, which is the same company page and returns 200.
- The Fazier launch badge link (`https://fazier.com/launches/www.kargarbusinessservices.com`, home page footer area) now `307`s to `fazier.com/`. The listing appears to be gone. **Needs a business decision:** restore the listing on Fazier, or remove the badge. A replacement URL was not invented.
- Facebook profile link: automated requests get `400` (Facebook bot wall). **Needs manual check** in a logged-out browser.
- The `.html` file names (`/privacy-policy.html`, `/services.html`, …) return 200 because the prerendered files are public. Each carries the clean-URL canonical, nothing links to them, and they aren't in the sitemap. Left as is. A `.html` → clean redirect would have to be proven loop-free against Vercel's rewrite to the same file on a preview deployment first. It is not worth that risk for URLs nobody links to.

**Audit changes (`frontend/scripts/seo-audit.ts`, `scripts/seo/crawl-utils.ts`)**

- Probes are now assertions (status, final redirect target, maximum hops, canonical). New probes cover `/privacy-policy/`, `/privacy-policy/?ref=x`, `/privacy-policy`, `/services`, `/sectors`, the `.html` variants, `/category/services/` and `/about-us`. A mismatch is CRITICAL, so the CI step `npm run seo:audit -- --strict` fails.
- Every redirect is traced hop by hop with GET, and loops and chains that don't end in 200 are detected. This was mutation-tested by injecting a `/privacy-policy` → `/privacy-policy/` loop: 9 critical issues, exit 1.
- A link inventory with anchor text, link type (navigation/footer/breadcrumb/CTA/image/content), status, hops and recommended action goes to `internal-links.csv`. Linked files (images, PDFs) are also status-checked.
- `--external` checks outbound links and JSON-LD `sameAs` URLs two at a time, with GET, a 15 s timeout and one retry. It separates dead (404/410), blocked (401/403/999), rate-limited, server and network errors, and links redirected to a different page. It never fails `--strict`.
- Against production, a scheme/host/slash canonicalization matrix is written to `canonicalization-matrix.csv`.

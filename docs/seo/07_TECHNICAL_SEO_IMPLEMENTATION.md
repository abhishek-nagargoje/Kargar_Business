## Rendering and metadata
- **No architecture change.** The existing build-time prerender (`frontend/scripts/seo/prerender.ts`, Playwright + `@sparticuz/chromium` on Vercel) renders the new routes automatically. The build prerendered **45/45 routes** (44 indexable + the 404 probe).
- Raw prerendered HTML for every changed or new page was checked for one `<h1>`, a unique `<title>`, a self-referencing absolute canonical, `index, follow`, and JSON-LD (Organization, LocalBusiness, Service, FAQPage, BreadcrumbList; Article on the guide).
- New titles fit the validator's 21–31 character rule before the " | KARGAR Facility Management" suffix. Descriptions are 140–160 characters and contain the contiguous primary keyword.

## Sitemap, robots and rewrites
- `public/sitemap.xml` regenerated: **44 URLs** (was 41). `validate-sitemap` confirms every URL returns 200, is self-canonical and is indexable.
- `lastmod` comes from the last git commit of each page's content file. **Until this work is committed, the three new URLs show the previous commit date of `security.ts`/`guides.ts`.** Vercel builds from the commit, so the deployed sitemap will carry the true commit date. Do not hand-edit `lastmod`.
- `vercel.json`: clean-URL → `.html` rewrites for the three new routes were generated by `scripts/seo/index.ts`. No redirects added; no chains.
- `robots.txt` unchanged (regenerated identical): `Allow: /`, `Disallow: /admin`, sitemap declared.

## Structured data
- No schema code changed. Service nodes for new pages come from `PuneLandingPage.tsx` (`provider` → `#organization`, `areaServed` Pune). FAQPage is generated from the visible FAQ strings. Article (guide) comes from `GuidePage.tsx` with organisation authorship and real dates.
- `validate-schema`: PASS.
- **Not added:** licence or certification properties, `aggregateRating` or review markup. Nothing verified supports them.
